# Data model: An administrator creates a user with a role (US-09)

## `users` (existing, unchanged)

Created with `status = ACTIVE`, `lastLoginAt = null`, server-generated `id`, `createdAt`,
`updatedAt`. `customerId` set only for `[CUSTOMER]`. Email unique on `lower(email)` (existing index).

## `audit_records` (new, migration `…-CreateAuditRecords`)

| Column | Type | Notes |
|---|---|---|
| `id` | uuid PK | generated by the domain |
| `actorId` | uuid not null | acting admin (token `sub`, re-checked) |
| `action` | varchar(64) not null | `AuditAction` value, e.g. `USER_CREATED` |
| `targetId` | uuid not null | the user created / changed |
| `before` | jsonb null | `null` for a creation |
| `after` | jsonb not null | `{ "roles": ["ADMIN"] }` for `USER_CREATED` |
| `occurredAt` | timestamptz not null | change time (`Clock`) |

- No foreign keys (R3). No secondary index yet (US-11 adds what its queries need).
- Trigger `audit_records_append_only` (`BEFORE UPDATE OR DELETE … FOR EACH ROW`) raises
  `audit records are append-only`. `down` drops trigger, function and table.
- `before` / `after` never hold a password, hash or token (domain builds them from roles only).

## Domain

- `AuditAction` enum: `USER_CREATED` (US-10 / US-07 follow-up add more).
- `AuditRecord` (immutable value): `id`, `actorId`, `action`, `targetId`, `before`, `after`,
  `occurredAt`; factory `AuditRecord.userCreated(actorId, user, at)` → `before = null`,
  `after = { roles: user.roles }`.
- `User.createByAdmin(email, name, passwordHash, roles)`:

| `roles` | Result |
|---|---|
| `[CUSTOMER]` | `registerCustomer`: new `customerId` ≠ `id`, records `UserRegistered` |
| `[ADMIN]` | `registerAdmin`: no `customerId`, no event |
| anything else (empty, both, repeated, unknown) | `UserValidationError` |

## Transaction (`AdminTx`, renamed from `UserStatusTx`)

Lock order unchanged and extended: `lockAdminChanges()` (same advisory key) → `findById(actor)` →
(US-07: `findByIdForUpdate(target)` …) → `insertUser(user)` → `appendAudit(record)` → commit.
`insertUser` maps the unique violation to `DuplicateEmailError` (rolls back the transaction).
